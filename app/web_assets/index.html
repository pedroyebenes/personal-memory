Interface guide

This app searches your local Obsidian (Markdown) vault that has been indexed into SQLite. Answers and search results are grounded in retrieved snippets, with file paths and references you can copy or open in Obsidian.

Header and status

  • Visualize opens a graph view in a new tab to explore the indexed vault structure and relationships, when available.
  • Refresh Index re-scans your vault, parses notes, re-chunks and re-embeds as needed, and updates the local database. It is disabled while a refresh is in progress. Check the warnings area for the last result or issues.
  • The status row summarizes: document and chunk counts, embedding coverage, the latest background job, and refresh state (idle, running, or the last run outcome). Your server config may set default on/off for reranking and concept boost, which the retrieval section reflects when the page loads.

Left rail: main tabs

  • Answers — ask questions; each answer is a workspace (tab) with its own question, sources, and mode.
  • Search — hybrid search only (no composed answer), with optional saved and recent queries.
  • Concepts — browse and filter the concept and structure entities stored for your vault (from your index’s concept layer).
  • Eval — run scripted retrieval checks to see whether expected notes and terms show up in the top results.

Workspaces (Answers)

Each time you Ask, a new workspace is created in the list. You can switch between them to compare prior questions, source lists, and whether the reply was extractive (quoted from notes) or LLM synthesis (when turned on and the provider is available).

Retrieval

  • Top K — how many chunks to retrieve as evidence for a question or a search. Higher values cast a wider net but may add noise; lower values are stricter.
  • Rerank (optional) — after the main hybrid score, a second pass nudges results where the query words (and phrasing) appear strongly in the title, section, and chunk text (for example exact phrase, term coverage, and terms close together). It can reorder the top set before you see them.
  • Concept boost (optional) — if the index has concepts/entities that match your query, chunks linked to those concepts get a small score increase so on-topic entity notes can rise in the list.
  • Advanced — Provider and model — choose the LLM provider and model name for features that use an API (Ollama, OpenAI, Gemini, NVIDIA, depending on your setup). The line below the dropdown shows whether the selected provider is available (for example API keys for cloud providers).
  • LLM synthesis — when on, a model turns retrieved snippets into a short answer with inline citations, when the provider works. When off, answers are extractive (built from your notes without generative text).
  • Query rewrite — when on, the app may rephrase your question to improve matching before search (uses the same LLM settings as synthesis, subject to your config). If rewrite fails, the original query is used.

Filters

Restrict results to notes that meet all of the active constraints (tags, aliases, path prefix, modified date range).

  • Tags / Aliases — comma-separated lists, matching the note’s tags and aliases in the index.
  • Vault path — only files whose path in the vault starts with this string (for example a folder name).
  • Modified from / to — last-modified range on the file.
  • Clear — removes all filters. The header shows how many filters are active for the current run.

Search view

Same retrieval settings and filters as Answers, but you only get the ranked chunk list (snippets, scores, and actions), not a full composed reply. Saved Searches and Recent Queries use the browser; they are not synced to the server.

Concepts view

Use the filter box and dropdowns to narrow concepts or structure entries, and optional method string to see how a concept was inferred. List fetches the current slice from the server for review.

Retrieval eval

The textarea holds JSON: either an array of test cases or an object with a cases array. Each case usually has a query plus expectations such as expected_paths and expected_terms. Run Checks calls the server to compare retrieval against those expectations. The eval panel’s rerank and concept-boost checkboxes only affect this check, not the main Answers/Search settings unless you mirror them.

Result cards and scores

Each result shows a final score derived from keyword + semantic + metadata, with optional rerank and concept contributions when those features are on. Copy Path, Copy Section / Source Ref, and Copy Markdown put citation-friendly strings on the clipboard. Open Hook uses an obsidian:// URL to open the file in the Obsidian app when installed.
